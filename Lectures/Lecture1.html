Introduction to NLP

Understanding Natural Language Processing — what machines need to learn about human language

What is Natural Language Processing?

Definition
NLP is the field of AI that enables computers to understand, interpret, and generate human language in a way that is meaningful and useful.
Core Goals
1
Understanding — parse meaning from text (syntax & semantics)
2
Ambiguity resolution — same word, different meanings
3
Context awareness — meaning depends on surrounding words
4
Generation — produce coherent, relevant text

NLP Tasks & Applications

🌍
Machine Translation
"Bonjour monde" → "Hello world"
😊
Sentiment Analysis
"Loved the product!" → Positive ✓
🏷️
Named Entity Recognition

❓
Question Answering
"Who wrote Hamlet?" → "Shakespeare"
📝
Summarization

💬
Text Generation
Prompt → coherent, contextual response

Why is Language Hard for Machines?

⚡ Lexical Ambiguity
🏦 "I went to the bank" → financial or river?
🤝 "I need a hand" → body part or help?
⚡ "The current" → water or electricity?
🔗 Coreference
"Hot in Paris. The city was crowded."
→ "city" = "Paris" — requires world knowledge
🌍 Context Dependency
"Fly to Paris" vs "Paris Hilton"
→ Same word, completely different meaning
📐 Syntax ≠ Semantics
"Colorless green ideas sleep furiously"
→ Grammatically correct, semantically nonsense!
💡 The Solution
We need representations that capture meaning in context → latent space representations

Latent Space Representation

What is a Latent Space?
Imagine giving every word a location on a map. Words with similar meanings are placed close together; unrelated words are far apart. That "map" is the latent space — a mathematical coordinate system where position = meaning.
What are "Latent Coordinates"?
A word is assigned a list of numbers (e.g. 300 numbers). These numbers are the word's coordinates in the latent space — its hidden (latent) fingerprint of meaning.
Just like GPS coordinates locate a city on Earth, latent coordinates locate a word in meaning-space.
Key Properties
✦ Semantic similarity = geometric closeness
✦ Relationships preserved as vector directions
✦ Analogies = vector arithmetic

Word Vectors & Arithmetic

[king] − [man] + [woman] ≈ [queen]
More Examples
[France] − [Paris] + [Berlin] ≈ [Germany]
[walking] − [walk] + [swim] ≈ [swimming]
[doctor] − [man] + [woman] ≈ [nurse]
💡 Why This Matters
The vector space encodes meaning as geometry. Mathematical operations on vectors = reasoning about language and concepts.

Measuring Similarity: Cosine Similarity

The Formula
cos(θ) = (A · B) / (‖A‖ · ‖B‖)
Measures the angle between two vectors — direction similarity, not magnitude.
Interpretation
+1
Same direction → identical meaning
0
Perpendicular → unrelated concepts
−1
Opposite direction → antonyms
sim(king, queen) ≈ 0.91
sim(Paris, France) ≈ 0.88
sim(king, fish) ≈ 0.12
Cosine similarity — angle between vectors matters, not length

From Text to Vectors

Evolution of text representation — from simple word counts to contextual neural embeddings

The Text Representation Challenge

The Core Problem
Computers understand numbers, not words. We must convert text to numerical vectors that preserve meaning, context, and relationships.
Requirements
1
Semantic — similar words → similar vectors
2
Contextual — word meaning changes with context
3
Relational — encode word-to-word relationships
4
Dense — compact, not sparse one-hot vectors

Bag of Words (BoW)

How It Works
Represent a document as a vector of word counts over a fixed vocabulary. Vocabulary size = vector dimensions.
✓ Simple, fast, interpretable. Good baseline for document classification.
Limitations
No word order — "dog bites man" = "man bites dog"
No semantic similarity — "king" ≠ "ruler"
Sparse, huge vectors (vocab ≈ 50k+ dims)
Common words dominate (the, a, is...)
No context — one meaning per word

TF-IDF Term Frequency – Inverse Document Frequency

The Idea
A word is important if it appears frequently in this document but rarely across all documents. Downweights common words like "the".
t = term  |  d = document  |  N = corpus size
freq(t, d)
|words in d|
TF(t,d)
×
log( N / df(t) )
IDF(t)
=
TF-IDF(t, d)
📖 Worked Example
Doc: "Paris is the capital of France" (6 words)
Corpus: N=100 docs; "Paris" in 10 of them
TF  = 1/6             ≈ 0.167
IDF = log(100/10) = log(10) ≈ 2.30
TF-IDF = 0.167 × 2.30 ≈ 0.38
✓ Improves over BoW — reduces noise from common words. Great for search & retrieval.
Word Weight Comparison
Limitations
No word order or syntax awareness
Synonyms treated as completely different words
No semantic relationships encoded
"bank" (river) = "bank" (finance) — no context

Word2Vec Mikolov et al., 2013

Key Innovation
Train a shallow neural network to predict context words. The hidden layer weights become dense, meaningful word embeddings.
Two Architectures
CBOW: Predict target from context
"___ rules the land" → "king"
Skip-gram: Predict context from target
"king" → ["rules", "land", "castle"]
✓ Breakthrough
First dense, semantically meaningful embeddings. Enables word arithmetic!
Limitations
Static — one vector per word always
"bank" same vector regardless of context
No sentence-level understanding
Out-of-vocabulary words unsupported

LSTM — Long Short-Term Memory

Key Innovation
Process text sequentially, maintaining a memory cell that selectively remembers or forgets information over long sequences.
Three Gates
■ State — what to keep in memory
■ Input — what new info to store
■ Output — what to output as hidden state
✓ Improvement
Handles long-range dependencies. Context-aware representations. SOTA for sequences before Transformers.
Limitations
Sequential — cannot be parallelized (slow!)
Vanishing gradient for very long sequences
Limited long-range context
No direct word-to-word attention

Language Models

Attention Is All You Need
Ashish Vaswani, Noam Shazeer, Niki Parmar, Jakob Uszkoreit,
Llion Jones, Aidan N. Gomez, Łukasz Kaiser, Illia Polosukhin
Abstract. The dominant sequence transduction models are based on complex recurrent or convolutional neural networks. We propose a new simple network architecture, the Transformer, based solely on attention mechanisms, dispensing with recurrence and convolutions entirely...
NeurIPS 2017 — The paper that changed everything in NLP

Task: Next Word Prediction

The Core Task
Given a sequence of words, predict the next word. Simple yet powerful — training on billions of documents at scale leads to deep language understanding.
Examples
Input: "The Eiffel Tower is located in"
→ Predict: "Paris" (p = 0.91)
Input: "Rivers flow into the"
→ Predict: "sea" / "ocean" / "lake"
💡 Why It Works
To predict next words accurately, the model must learn grammar, facts, geography, and world knowledge from training data.
Probability Distribution

Transformer Architecture Overview

Why Transformers?
Unlike LSTMs, Transformers process all tokens in parallel and relate any two positions directly via attention — no sequential bottleneck.
Key Components (Decoder-Only)
1
Tokenization — raw text → token IDs
2
Input Embedding — token IDs → dense vectors
3
Positional Encoding — inject position info
4
Multi-Head Self-Attention — relate all tokens simultaneously
5
Linear Layers — project hidden state to vocabulary probabilities
⚡ Key Advantage
Every token attends to every other token simultaneously. Long-range dependencies solved in a single step vs multiple steps for RNNs.
Scale
GPT-2: 1.5B parameters
GPT-3: 175B parameters
GPT-4: ~1T parameters (est.)
N× Transformer Blocks
Steps 4 & 5 form one block, stacked N times. GPT-2: 12 layers, GPT-3: 96 layers — each pass deepens the model's language understanding.

Positional Encoding

The Problem
The Transformer processes all tokens simultaneously, with no built-in notion of order. Without position info, "dog bites man" = "man bites dog" to the model!
The Solution
Add a positional encoding vector to each token embedding, giving the model unique position information for each slot.
PE(pos,2i) = sin(pos/10000^(2i/d)) PE(pos,2i+1)= cos(pos/10000^(2i/d))
pos=position, i=dim index, d=embedding dim
🧮
Combined input at position i:
zi = E(tokeni) + PE(i)
E(tokeni) → learned d-dim embedding
PE(i)      → fixed sin/cos vector
zi         → fed into Transformer
Sine/Cosine Waves at Different Frequencies

Self-Attention Mechanism

Three Projections
Q Query — "What am I looking for?"
K Key    — "What do I offer?"
V Value  — "What do I pass on?"
THE FORMULA
Attention(Q,K,V) = softmax(QKT/√dk)·V
Scale ÷√d_k prevents gradient issues
Key Insight
Every token can directly attend to every other token in one step — no sequential bottleneck!

Multi-Head Attention

The Big Idea
Run h parallel attention heads, each with different learned projections. Each head captures different types of relationships simultaneously.
What Each Head Learns
(these are examples — actual heads are emergent)
■ Head 1: Syntactic relations (subject-verb)
■ Head 2: Semantic similarity
■ Head 3: Coreference (it → entity)
■ Head 4: Positional / local patterns
The Formula
MultiHead(Q,K,V) =
Concat(head₁,...,headₕ) · W_O
where head_i = Attention(QW_i^Q, KW_i^K, VW_i^V)
⚡ Why It Works
Multiple heads = multiple "perspectives" on the same input. Richer, more nuanced representation.

Feed-Forward Network & Layer Normalization

Feed-Forward Network (FFN)
After attention, each token's representation passes through a position-wise FFN — two linear layers with ReLU activation.
FFN(x) = max(0, xW₁+b₁)W₂+b₂
Layer Normalization
Applied after attention and FFN. Stabilizes training and enables very deep networks.
LayerNorm(x) = γ · (x − μ)/σ + β
Residual Connections
Each sub-layer adds its input to its output:
output = LayerNorm(x + SubLayer(x))
→ Prevents vanishing gradients, enables depth
Complete Block (×N)
x = LayerNorm(x + MultiHeadAttn(x))
x = LayerNorm(x + FFN(x))
